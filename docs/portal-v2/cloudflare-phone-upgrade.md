# Upgrade D1 0004–0005, de pe telefon

**Situație:** baza `petru-ines-portal-eu` conține deja migrațiile 0001–0003 și contul administratorului. Nu relansa workflow-ul de migrare inițială. Portalul public rămâne momentan la versiunea Appwrite.

1. În Cloudflare → **My Profile → API Tokens → Create Token → Custom token**, creează un token nou, temporar, cu `Account → D1 → Read` și `Account → D1 → Edit`, limitat la contul `47b9f8498a9865c0fbbaca8f0f5cf59d` și cu expirare scurtă. Nu reutiliza tokenul revocat. Nu trimite tokenul în chat sau în imagini.
2. În [GitHub → repository secrets](https://github.com/petruandines/cleaning-services/settings/secrets/actions), creează secretul `PORTAL_D1_UPGRADE_TOKEN` și lipește valoarea tokenului doar acolo.
3. În [GitHub Actions → Portal D1 versioned upgrade (manual)](https://github.com/petruandines/cleaning-services/actions/workflows/portal-d1-upgrade.yml), apasă **Run workflow** pe ramura `main`, selectează `inspect` și lasă ambele confirmări goale. Trimite numai linkul rulării și statusul. Nu copia tokenul.
4. Verifică în jurnal mesajul `Verified EU D1 identity, initial migration history, columns and five pinned files.` și linia `Time Travel bookmark before upgrade`. Păstrează bookmarkul și data rulării într-un loc sigur; acesta este un punct de revenire pe termen scurt, nu un export independent. Cloudflare păstrează punctele Time Travel până la **7 zile pe planul Free**, respectiv **30 de zile pe Paid**. Restaurarea peste baza activă suprascrie datele ulterioare și se face numai după investigare. [Documentația Cloudflare](https://developers.cloudflare.com/d1/reference/time-travel/).
5. După inspect reușit, decide separat aplicarea. `apply` cere exact `APPLY PORTAL UPGRADE 6816004b-dc95-48c9-be52-9bd4131d157e` și `TIME TRAVEL VERIFIED 6816004b-dc95-48c9-be52-9bd4131d157e`. Nu porni `apply` până nu verificăm împreună jurnalul inspect. Dacă aplicarea se întrerupe, **nu apăsa Re-run**: verifică întâi schema și istoricul migrărilor.
6. După un eventual `apply` reușit, revocă tokenul din Cloudflare și șterge secretul GitHub. Publicarea Workerului nou și testele cu client fictiv sunt etape distincte.

Workflow-ul fixat la commitul revizuit verifică identitatea bazei, jurisdicția EU, cele trei migrații deja aplicate, structura dinainte și de după upgrade și hashurile fișierelor 0001–0005. În `inspect` nu execută SQL de modificare. Un export criptat păstrat separat și proba restaurării într-o bază distinctă rămân necesare înainte de utilizarea portalului cu date reale; Time Travel singur nu este suficient pentru recuperare de durată.
